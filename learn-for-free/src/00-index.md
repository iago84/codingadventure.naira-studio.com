# About this library

This is a library of **36 study volumes** (00 + 35 technologies). Every volume is
built from a free public tutorial or documentation site, following the same
structure so you always know where to find things.

The notes in each volume were **written from scratch** while working through the
source site's learning path: the summaries, explanations, exercises, tests and
code examples are original. The source sites are only used as a syllabus, and are
cited in each volume's Sources chapter.

## Summary

- One volume per technology, plus this index and study guide.
- Every volume has the same skeleton, so navigation is always the same.
- Each chapter ends with practice exercises (with solutions) and a mini test.
- Each volume ends with a cheat sheet and a final exam with an answer key.
- All content is in English and is original writing, not copied text.
- Code examples are written and tested by the author, with expected output.

## The learning contract

| In every chapter | What it is for |
|------------------|----------------|
| Summary bullets | Recall the whole chapter in two minutes |
| Concepts + diagrams | Understand, not just memorise |
| Runnable examples | See the idea working |

| Exercises + solutions | Prove you can do it yourself |
| Mini test + key | Check yourself immediately |

| At the end of every volume | What it is for |
|----------------------------|----------------|

# How to study a chapter

Follow this loop for every chapter, in every volume. It takes about 60 to 90
minutes per chapter and it works because you are forced to produce, not consume.

1. **Read the summary first (2 min).** Decide if you already know the material.
2. **Read the concepts once (10 min).** Do not code yet.
3. **Run every example (15 min).** Type it yourself, never copy and paste.
4. **Close the book and write the example from memory (10 min).**
5. **Do the exercises (20 min).** Look at the solutions only after trying.
6. **Take the mini test immediately (10 min).** Score yourself with the key.
7. **Anything you missed goes on a review list.** Re-read it the next day.

> **Tip.** The single biggest predictor of success is step 6: testing yourself
> immediately. It feels worse than re-reading and works far better.

## Spaced repetition

Review each chapter twice: once the next day and once after one week. Two fast
reviews beat one long re-read. A review is: read the summary bullets, then redo
the mini test from memory.

# How to run the code

Every code block is numbered so explanations can refer to specific lines. The
examples are minimal on purpose.

- They are self-contained and need no frameworks unless a chapter says so.
- The expected output is always shown under the example.
- If the output differs, read the code line by line before debugging.

## Worked example of the loop

```python
# 1  A minimal example, numbered lines, expected output below
# 2  Compute the average of a list and handle the empty case.
def average(values):
    if not values:
        return None
    return sum(values) / len(values)

print(average([10, 20, 30]))
print(average([]))
```

```text
20.0
None
```

Step 4 means you should be able to write that `average` function, from memory,
in under two minutes.

# Common mistakes that apply to all volumes

| Mistake | Why it hurts | Fix |
|---------|--------------|-----|
| Reading without running code | False confidence | Type every example |
| Looking at solutions too early | You learn nothing | Struggle for 10 min first |
| Skipping the mini tests | You never find the gaps | Always take them |
| Moving on with an unsolved bug | The gap compounds | Debug before continuing |
| Binge-reading chapters | Retention collapses | Two chapters a day, maximum |
| Never re-reading | Memory decays | Review next day + 1 week |

# Mini test

1. **Multiple choice:** what is the recommended maximum number of new chapters
   to study per day?
   - a) as many as possible
   - b) two
   - c) ten
   - d) it does not matter
2. **True or false:** you should copy and paste every code example to save time.
3. **Multiple choice:** which step in the study loop gives the biggest recall boost?
   - a) reading the concepts twice
   - b) watching a video first
   - c) taking the mini test immediately
   - d) reading the summary
4. **True or false:** the summaries exist so you can skip the chapter.
5. **Ordering:** put these in the right order: do exercises, read summary, take
   mini test, run examples.
6. **Short answer:** what should you do the day after finishing a chapter?
7. **Multiple choice:** which track starts with 01 HTML and 02 CSS?
   - a) Back end
   - b) Front end
   - c) DevOps
   - d) Security

## Answer key and explanations

1. **b** - two chapters a day keeps retention high; bingeing collapses it.
2. **False** - typing examples yourself forces you to read every character.
3. **c** - immediate retrieval practice beats re-reading.
4. **False** - they are for recall and review, not a substitute for the chapter.
5. **read summary, run examples, do exercises, take mini test** - that is the loop.
6. **Review it** - read the summary bullets and redo the mini test, then again
   after one week.
7. **b** - Track A (front end) starts with HTML and CSS.
